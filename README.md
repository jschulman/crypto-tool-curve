# Crypto Tool Curve

Tracking when crypto-native accounting tooling crosses meaningful adoption in the middle market — with data, not opinion.

**[View the live dashboard →](https://jschulman.github.io/crypto-tool-curve)**

## What Is This?

An open-source dashboard that aggregates publicly-available job posting data to answer one question: **Is purpose-built crypto-accounting tooling actually being adopted?**

The **Tool Adoption Rate** measures what percentage of open crypto-native middle-market finance roles mention any of the purpose-built crypto-accounting platforms (Bitwave, Cryptio, TaxBit, SoftLedger, Ledgible, Integral, Cryptoworth). A higher rate means crypto finance teams are standardizing on dedicated tooling. A near-zero rate means companies are still cobbling subledgers together in spreadsheets.

| Adoption rate | Phase | What It Means |
|-------|-------|---------------|
| 0–5% | Spreadsheet | Sector is still hand-rolling crypto accounting in Excel |
| 6–15% | Curious | Early adopters; tooling is in JDs but not yet table-stakes |
| 16–40% | Standardizing | Real demand signal; vendors crossing chasm |
| 41–100% | Established | Crypto-accounting tools are required-skill in JDs |

## Signals

| Signal | Source | Frequency | What It Measures |
|--------|--------|-----------|-----------------|
| Tool Adoption Rate | Greenhouse / Ashby / Lever public job-board APIs | Daily | % of open finance JDs mentioning any tracked crypto-accounting tool |
| Per-Tool Count | Greenhouse / Ashby / Lever | Daily | Mention count per tool (Bitwave, Cryptio, TaxBit, SoftLedger, Ledgible, Integral, Cryptoworth) |
| Tracked JD Count | Greenhouse / Ashby / Lever | Daily | Total open Tier-1/2/3 finance JDs in the corpus (the denominator) |
| Adoption Over Time | Computed from snapshots | Daily | Time series of the adoption rate |

Every signal uses **free, public data sources** — no proprietary APIs, no paywalls.

## Design Principles

- **Data, not opinion.** The dashboard presents signals. It does not editorialize.
- **Reproducible.** Methodology is open. Anyone with a list of crypto-native companies and access to their public careers pages can compute these numbers.
- **Automated.** Updated daily on a schedule. No human curation of the daily data.
- **Durable.** Only signals with reliable, ongoing public sources are included.
- **Accessible.** Single page. No login. No paywall. Mobile-friendly.

## Architecture

```
data/snapshots/         Versioned daily JSON snapshots
data/latest.json        Most recent snapshot (what the dashboard reads)
docs/                   Static dashboard (HTML/JS/CSS — GitHub Pages)
.github/workflows/      Automated refresh schedule
METHODOLOGY.md          How every signal is computed, with sources
```

Data is generated by scanning a curated list of crypto-native middle-market companies' public job-board APIs (Greenhouse, Ashby, Lever), then string-matching JD bodies against a fixed list of tool names. The target list and aggregation code are maintained privately; only aggregate metrics are published here. See [METHODOLOGY.md](METHODOLOGY.md) for details.
